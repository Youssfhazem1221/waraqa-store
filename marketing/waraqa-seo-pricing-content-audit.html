SEO Readiness Audit

Pre-launch, code-based audit — no live domain exists yet, so Core Web Vitals and real indexation can't be tested. Re-run live once deployed.

Critical

Bilingual content has no crawlable URL

LanguageContext.tsx always initializes locale to en, then flips client-side after mount via localStorage/navigator.language. There's no /ar URL, no i18n routing config — one URL serves both languages via client state only.

Root metadata already targets Arabic terms (دفتر رسم, سكتش بوك) and full Arabic copy exists in translations.ts — none of it is reachable by a URL Google can index as Arabic.

Fix: move to URL-based locale routing (/ar/..., /en/...) so each language is its own indexable, hreflang-linked page. Architecture change, not a metadata tweak.

High

No sitemap or robots file

No src/app/sitemap.ts, src/app/robots.ts, or public/robots.txt found anywhere in the repo.

Fix: add both as App Router route handlers; list /, /shop, /about, and every /product/[slug] (already enumerated via generateStaticParams).

High

/shop and /about have no page-specific metadata

Both are 'use client' components — Next.js can't export metadata from a client component, and neither has a server wrapper supplying one. Only /product/[slug] correctly uses generateMetadata.

Fix: wrap each in a thin server component that exports metadata, keeping the interactive parts client-side.

Medium

Domain mismatch in metadata

metadataBase falls back to waraqa-store.vercel.app; openGraph.url is hardcoded to waraqa.store. These need to agree once a production domain is set.

Medium

No Product/Offer structured data

Product pages have price, images, and description available server-side but emit no JSON-LD. Low effort to add given the data already exists in products.json.

Working well

What's already solid

Per-product generateMetadata, bilingual keywords in root metadata, breadcrumb navigation, and fully static product URLs via generateStaticParams — sitemap generation will be trivial once added.

Prioritized action plan

  1. Decide and implement URL-based EN/AR locale routing before investing further in Arabic content.
  2. Add app/sitemap.ts and app/robots.ts.
  3. Give /shop and /about real per-page metadata.
  4. Fix the domain mismatch once production URL is final.
  5. Add Product/Offer JSON-LD to product pages.
  6. Re-run this audit live once deployed — Search Console, Core Web Vitals, real indexation.

Highest leverage

Free-shipping threshold (800 EGP) is too high

Every SKU is 120–250 EGP, so a single-item order needs 3–4+ books to hit free shipping. The 50 EGP flat fee is a +42% effective price increase on the cheapest item.

Fix: lower the threshold to ~350–400 EGP, or launch a bundle priced just under it so "add one more for free shipping" is actually reachable.

No bundling despite a catalog that begs for a starter set

A "Try All Three Weights" bundle (150 / 250 / 320gsm, ~10% off, ≈522 EGP) solves the "which weight do I need" indecision and the shipping-threshold gap in one product.

GSM is the value metric, but it's invisible on the shop grid

Price scales sensibly with paper weight, but only a buyer who already knows what gsm means can see that logic.

Fix: add a plain-language weight-tier badge ("150gsm — everyday sketching" / "250–320gsm — ink & wet media") on shop cards and PDP.

Keep as-is

Round-number pricing fits the brand

Charm pricing (179 vs. 180) usually lifts conversion slightly, but Waraqa's stated value is explicitly "Fair Pricing" as part of an honest, anti-corporate story. Round numbers read as an honest flat price here — don't chase the tactic against the brand's own positioning.

Large Sketchbook's price looks unexplained next to its neighbors

Priced the same as the A5 Kraft (180 EGP) despite lower gsm and fewer sheets — the real driver is sheet area (~5× an A5 sheet), which isn't stated anywhere.

Fix: add one line to the description calling out sheet size as the value driver.

Prioritized actions

  1. Lower the free-shipping threshold or launch a starter bundle.
  2. Add gsm/weight-tier badges to shop grid + PDP.
  3. Add the sheet-size explainer to the Large Sketchbook.
  4. Keep round-number pricing — don't charm-price.
  5. Validate with real A/B tests once order volume exists.
